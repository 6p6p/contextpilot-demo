# MVP v1.1 — Phase A / Phase B

2026-11-06。无真实模型、搜索、Embedding、邮件调用；不部署/Push，不清理旧数据。Corpus v1 Golden未改。

## Phase A 业务质量

根因与修复：

- A1：此前只允许单条原文的current/latest关键词结论，官方状态表与发布页分散时无法作结论。新增受约束的release结构（版本、支持状态、原文索引），服务端验证官方域名、近期性、版本一致、状态同主版本与冲突后生成中文概括；不接受自由编造事实。逐字引文仍逐字验证。不能证明最新补丁时明确保留限制；本轮不增加补充搜索调用，不按版本大小猜最新。官方机构按任务识别。冻结状态表/发布页/旧文/冲突/伪造索引等测试通过。
- A2：仅验证“引用真实”不够，恶意原文可被风险分析转成跟进建议。现在验证证据后检查实际整行权限注入，剔除其风险/行动；Corpus第11行固定复现初跑失败、修复后通过。不可信旧行不进入新PPT/邮件预览。明确行动/风险建议/待确认问题按origin区分，缺少人/日期保持未知，不要求固定数量。origin在库中是text，新增question类型不需DDL。已有人工编辑及来源保留，不自动批量删除旧误识别记录。
- A3：词命中与同源扩展可偏向同名其他项目。新增项目ID与原文分句绑定，并在候选/最终选择双层校验；同名不能把FIN的苏州/日期用于7421。当前会话刚提供了指定项目事实时优先当前上下文，不无意义调用记忆选择器；独立跨会话仍检索持久化来源。正文只显示选中事实，原文/观察时间保留在折叠引用。无项目ID的模糊同名问题仍需澄清，不声称算法能理解任意隐含项目。
- A4：旧实现只检查分析版本，待办修改未触发草稿过时。现在使用数据库精确时间比较待办变更与草稿最后保存，编辑与确认以会议行锁串行；确认不更新内容基准时间。确认/发送入队/发送前均检查待办是否变化。旧确认/正文不自动改写；提供只读最新风险/明确待办预览，用户复核保存才生成新版本并需重新确认。建议/待确认不冒充正式分配行动。

验证：新7项质量测试中，A1/A2/A3对应旧行为初跑失败后修复；check/test共193项（最终命令回执为准）、Corpus17、生产Chrome E2E2通过。受控真实PostgreSQL+外部全替身8项，Run `b4e6c5cd-6fac-458d-a14b-bdf20785c9f0`；66新记录、7本地Storage替身对象，旧记录哈希变化0，全部保留。新增T04断言待办修改后stale、预览不写原正文、旧确认拒绝；T05新会话与PDF模式独立测试沿用。未执行云DDL。

仍待人工：实际模型对官方多源的完成率、同名语义、会议分类与草稿复核操作。本轮代理付费API次数0；用户此前真实调用不在本轮费用统计内。Phase A本地提交后才进入Phase B。

## Phase B 增量状态方案

计划0009仅新增三个nullable timestamptz字段：conversations.archived_at、documents.removed_at、meeting_todos.dismissed_at。旧行为默认不变，不删除向量/原文件或任何历史记录。会话归档后不列入新历史列表或新记忆召回；PDF移除后不进入新RAG/PPT检索，历史引用下载保留；忽略待办后不进入新正式邮件/PPT清单，源会议及人工字段保留。标记判定使用to_jsonb，管理写入口在字段缺失时报需配置，不偷偷变成纯前端隐藏。新版部署仍须先应用0009；旧Railway程序读取旧字段保持结构兼容，不代表旧站已具备新过滤语义。

用户随后明确批准。已审查SQL并离线验证仅3 nullable字段、无默认值/回填/删除，再受控执行0009。迁移前检查父版本必须为0008，迁移后核对3字段is_nullable=YES、当时非NULL数0，忽略新增键后的旧记录ID/内容哈希完全一致。收据在`.acceptance/mvp-v1.1/migration-receipt.json`。Drizzle schema和0009 snapshot同步，仅增加批准的3列。旧Railway旧字段读取结构兼容，**旧程序不会自动执行新版的归档/移除过滤语义**；本轮未部署，不声称公网站已更新。

## Phase B UI/UX v2 交付

- 以聊天为中心：左栏产品入口+会话历史，中央可读宽度、内部聊天滚动区、底部输入；知识库、会议、记忆为保持状态的辅助视图，PPT从对话顶部或导航进入。桌面/390px窄屏均检查。减少工程卡片堆叠，连接状态缩为标题栏。历史PPT初次加载不自动撑开工具，只有新任务或主动入口展开。
- SafeMarkdown是受限React渲染器，支持标题/粗体/有序无序列表/代码/引用/HTTP(S)链接；不使用innerHTML，原始HTML为文字、危险scheme不形成链接。没有安装框架或Markdown依赖，不承诺完整CommonMark表格/嵌套扩展。
- 自动跟随只操作消息容器；主动发送定位底部，用户上滚后新结果/刷新不拉回，切会话单独恢复。失败提供重新编辑，不自动重发。窄屏检查输入框在视口内，页面不被长消息撑高。
- 会话改名服务端持久化；删除为归档，二次确认说明消息/来源/PPT保留，列表和新的记忆召回排除归档会话。历史引用仍可鉴权读取，正在回复的会话不能归档。
- PDF移除为逻辑标记，服务端列表、RAG、PPT检索及Worker新领取排除；向量与原始私有对象不自动删除，历史下载保留。进行中的任务可能完成，但新检索仍受标记约束。没有按名字清理。
- 待办忽略/恢复为版本CAS软状态，保留证据、负责人、日期和手工编辑；新草稿预览/正式内容和新PPT todo来源排除忽略项。重新分析不清空忽略标记。明确行动、建议、待确认、完成状态有视觉区分，未知字段不补值；保存/忽略反馈明确。
- 草稿仍在具体会议风险/待办之后，展示版本、确认、过时信息；最新待办预览不改库，复核保存才版本递增；真实发送继续关闭。旧记录未存逐项版本快照，不能从现有时间戳恢复所有历史编辑过程，旧草稿仍需人工核对，不能自动认证为最新正文。
- 记忆刷新提供busy/失败/最近完成时间，事实与原文来源分层折叠，内部任务ID归入诊断区域。PPT复用全站认证，状态/历史下载恢复，未改生成引擎和私有鉴权。

### 人工 UI/UX v2 复测顺序

在本地新版、确认预算与后台队列后打开工作台（启动含真实配置的Worker前仍需授权，不能仅为看UI就消耗旧排队任务）。优先用已持久化资料进行不调用模型的交互检查：

1. 左栏切换五个入口，返回对话不丢输入；390px及桌面检查布局/输入区和长历史滚动。Markdown代码里的HTML应为原样文字，不能运行。
2. 新建自己的合成会话，改名；删除先取消、再确认归档。列表不再出现，但原引用与已生成PPT不丢。不要拿他人或旧验收记录做删除演练。
3. 对自己新上传的测试副本选择移除并确认，文件从列表/新检索排除，历史消息中的私有原件链接仍可核对。旧Railway未更新，不能据其旧列表判断本地移除失败，也不能假定旧站已经遵守新标记。
4. 选完成会议，保存负责人/日期，核对反馈；忽略无用项并刷新，检查原文还在而最新草稿预览/PPT待办来源不包含它。恢复需新版本；已完成与待处理应可区分。
5. 旧草稿不能被后台覆盖；按最新待办预览→复核保存→确认新版本，旧确认不能发送新内容。真实发送显示未启用。
6. 记忆页点刷新，看busy、完成时间、错误与折叠来源；PPT页确认无第二口令，已有文件历史下载可恢复。
7. 真实多源搜索概括、会议分类、同名召回及新PPT生成仍按Stage B原指南复测、记录真实来源与用量；代理本轮没有运行这些付费步骤，不宣称现场问题全部关闭。
