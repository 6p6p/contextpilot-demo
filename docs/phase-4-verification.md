# Phase 4 会议分析验收记录

本阶段：会议 TXT、风险证据、可编辑待办和邮件草稿。真实业务用例已分次通过；没有真实邮件发送、部署、推送或创建云资源。原始 docs/assignment.txt 未修改。

## 实现与配置

保持模块化单体及既有技术栈，无新增依赖。主要变更：

- shared/meetings.ts：Zod 分析、证据、编辑和详情契约。
- apps/api/src/meetings/{analysis,service,routes}.ts：UTF-8 校验、分段提取/合并、精确证据、持久化任务、去重、版本及草稿确认。
- apps/api/src/db/schema.ts、drizzle/0003*、0004*：7 张新领域表，启用 RLS；新增表/约束/索引迁移已审查并真实执行，没有破坏性 SQL。
- 现有 Storage 支持 text/plain；原有 PDF 默认行为保留。现有模型适配器为会议显式启用 JSON mode，截断结构化输出明确失败。
- apps/web/src/MeetingPanel.tsx、meetings.css、App.tsx：在统一工作台集成上传、分析、证据、待办编辑、草稿预览/保存/确认。
- 测试、合成 TXT 样本、长文生成器、独立真实验收配置和遥测；README、SPEC、TASKS、AGENTS、.env.example 更新。

复用用户现有私有 contextpilot-files Bucket（用户确认 MIME Any / 50 MB），未改变权限或设置。服务端独立限制 .txt + text/plain、严格 UTF-8、非空、1 MiB / 64000 UTF-16 单元 / 4000 行 / 每行 2000 单元。每次 Storage 操作检查 Bucket 为 Private；不暴露对象密钥或凭据。原始字节保存及 SHA-256 去重，CRLF 只在分析文本中规范化，保留空行与物理行号。

段长约 8000 UTF-16 单元，重叠 2 行，最多 16 段；长文先分段提取再全局合并，保留源行动项和基础事实，考虑跨段风险与后续解除条件。不截断超限内容。会议模型为实际 deepseek-flash，独立 MEETING_MAX_TOKENS=8192、MEETING_TIMEOUT_MS=90000；普通聊天 1024 / 45000 不变。PDF 仍用 SiliconFlow BAAI/bge-m3 / 1024 维，本阶段未更换 Embedding 或向量结构。

Zod + 原文精确匹配校验证据、事实、负责人、完整截止日期。未知保持 null。风险影响属于潜在分析，需人工复核。无明确行动项的风险可生成明确标记的跟进建议，未知负责人/日期不填造。缺失/无效 JSON、证据或截断输出一律 failed，无半成品发布，不自动重试模型。

上传状态与租约在 PostgreSQL 持久化，5 分钟租约/30 秒续租，进程中断最多恢复一次；因此中断恢复可能再次计费。成功分析事务性发布；重新分析失败保留先前成功版本。原始字节相同的上传返回同一记录、不重复分析；待办按源任务/证据匹配，保留人工 owner/date/status。草稿不被重新分析覆盖，旧版本必须复核保存。

收件人默认空，必须用户输入。确认保存不可变版本/收件人/正文/分析关联快照，deliveryState 永远 not_sent。没有发送路由或邮件服务调用。

### 真实 Storage + LLM + 浏览器/API

设置 `PLAYWRIGHT_CHANNEL=chrome`，使用 `npm run test:e2e:meetings -- --grep <用例>` 分次验收，重试数为 0。三个业务用例最终各自通过，未宣称一次全套绿：

1. 有风险、多风险/多待办、原文行号、未知字段：通过（约 1.4 分钟）。真实 UI 上传、待办编辑、草稿显式填写收件人/保存/确认；重复上传不新增分析；重新分析后人工字段、待办数量、草稿内容保留，旧草稿要求复核；刷新恢复。
2. 无风险、缺日期/地点/负责人、恶意提示注入：通过（50.8 秒）。无风险会议没有强制风险或草稿；注入文本未生成攻击者收件人或伪造负责人/截止日期，所有草稿未发送。
3. 长会议：通过（约 1.1 分钟），实际分 2 段加全局合并；风险关联第 2 行与第 133 行，跨段行动项保留，未知字段仍空。

保留的失败过程：首次风险输出非法 JSON；长文一次事实并非原文摘录，被拒绝；随后一次结构化输出达到 4096 token 截断，被拒绝。针对格式问题增加会议专用 JSON mode/明确示例，针对截断将会议独立上限调至 8192，并显式识别 length。未放宽原文验证、修补虚假事实或将失败当成功。期间诊断返回 HTTP 200 不等于业务分析成功。

## 保留问题与边界

- OPEN：Phase 3 一次未复现上传 HTTP 500，尚未定位根因，不能标记修复。
